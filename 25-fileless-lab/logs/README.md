## What to look for

Both trees report `8 passed, 0 failed` on `final.sh`, and that is not a mistake.
`final.sh` asks whether each pattern *executes*, and the buggy loaders do execute —
finding #1 destroys the caller's file while succeeding, and #2 only changes which
error is printed when the payload is missing. Neither is a pass/fail failure, which
is precisely why they survived into a published document. They show up here:

    20-v1.1-edge.txt:  after: victim GONE (unlinked by loader)
    10-v1.2-edge.txt:  after: victim EXISTS

    20-v1.1-detection_lint.txt:  5 of 7 auditd rules PARSES-OK
    10-v1.2-detection_lint.txt:  7 of 7

`10-v1.2-gate_compile.txt` is the longest and the most useful for a reader: it shows
the Appendix C gate failing to compile alone, then compiled against a real `vmlinux.h`
generated from kernel BTF, leaving only the gaps the document expects the implementer
to fill.
